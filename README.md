# MemoryPilot

MemoryPilot 是 SillyTavern 的可视化记忆管理与召回扩展。它可以把聊天中的重要事件整理成可搜索、可编辑、可回退的记忆，并在合适的时机将记忆注入角色或系统 Prompt。

4.0.0 使用统一面板，保留原有记忆存储与召回逻辑，同时加入 Anima、Horae、自动楼层总结、主题切换、备份恢复和一键更新等功能。4.2.0 起支持接入 OpenAI 兼容 Embedding 接口做向量 / 混合召回。

## 入口与第一次使用

安装后，打开 SillyTavern 的魔法棒扩展菜单，点击 **MemoryPilot** 即可进入面板。

面板内统一提供：

- 记忆管理
- 召回监控
- 设置
- API 配置
- 新手指引

输入区上方的快捷按钮默认隐藏。如有需要，可在“设置”中单独打开；它与魔法棒入口是同一个功能，不会重复创建多个入口。面板支持白天/黑夜主题，主题只改变界面外观，不会改变记忆或召回数据。

第一次使用时，建议按“新手指引”完成以下步骤：

1. 在 API 配置中填写一个可用的 OpenAI 兼容、Claude 或 Gemini 接口。
2. 新建记忆，或从小白X、Anima、Horae 导入已有内容。
3. 为记忆设置主关键词和召回类型。
4. 在角色卡或系统 Prompt 中加入：

   ```text
   {{getvar::mp_recall_pin}}
   {{getvar::mp_recall_ctx}}
   ```

## 记忆管理

记忆列表支持搜索、编辑、删除、批量删除和撤回删除。每条记忆可以包含：

- 事件名与摘要
- 主关键词、辅助关键词、人物/实体关键词
- 时间标签与时间值
- 楼层范围
- 召回类型
- 来源

召回类型分为：

- **常驻**：跨较长时间仍然成立的核心设定，数量应尽量少。
- **主要触发**：与当前剧情直接相关的重点事件。
- **次级触发**：有帮助但不应占用过多上下文的位置。

列表还提供过滤、批量关键词重构、批量合并、导入和导出 JSON。外部总结导入后，可以选择“未重构……”的记忆，再执行“批量重构关键词”。

列表顺序可以手动整理：按住每条记忆左侧的 `⋮⋮` 拖到目标记忆的上半或下半即可，鼠标与触屏通用，在筛选或搜索视图下也可以使用（移动的是完整列表中的相对位置）。“记忆筛选与批量操作”里还提供“按楼层 新→旧 / 旧→新”一键整理；没有楼层范围的记忆会保持原顺序放在最后。

## 小白X、Anima 与 Horae

面板提供三个独立的外部来源页：

- **小白X总结**：读取当前聊天中的小白X事件，可批量导入并设置召回类型。
- **Anima总结**：读取当前聊天绑定世界书中的 Anima 总结，可批量导入并设置召回类型。
- **Horae记忆**：读取 Horae 的原始时间线事件，包括已被 Horae 压缩隐藏的事件。Horae 后续压缩不会修改已经导入 MemoryPilot 的记忆，也不会重复导入同一事件。

召回设置中有独立的 Anima 去重和小白X去重开关。开启后，只会过滤本轮已经由对应外部系统注入的同源记忆，不会影响手动记忆或其他来源。外部系统不可用、读取失败或没有数据时，会自动回到普通召回行为。

## 召回

MemoryPilot 默认使用 v34 引擎，也可以在“设置”中切换到 v32。

两种引擎都会：

- 在角色消息收到时进行正常召回；
- 读取最近一段聊天上下文；
- 要求主关键词命中，并支持中文弱匹配；
- 根据辅助关键词、楼层距离、记忆新鲜度和召回类型进行排序；
- 将命中的普通记忆暂时保留在 Sticky 中，避免刚出现就消失；
- 将常驻记忆与普通召回分别写入 `mp_recall_pin` 和 `mp_recall_ctx`。

`every` 控制多久重新评估一次；非评估轮会沿用上次结果，同时实时更新常驻记忆。`contextWindow` 控制参与匹配的最近消息数，`maxRecall` 控制普通召回数量，`stickyTurns` 控制 Sticky 保留轮数。

`recentFloors`（设置中的“最近楼层记忆数”，默认 0 = 关闭，上限为当前记忆总数）会把楼层号最大的 N 条非常驻记忆每轮直接注入 `mp_recall_ctx` 的最前面：不需要命中关键词，也不占用 `maxRecall` 名额。被选为最近楼层记忆的条目会从关键词触发候选和 Sticky 输出中剔除，因此同一条记忆不会重复发送；没有楼层范围的记忆不参与此项。它与原有关键词召回并行工作，关闭后行为与之前完全一致。填入的 N 超过当前记忆总数时，保存时会自动按总数截断。

v34 会让主要触发优先填充名额，并在满足条件时保留至少一个次级触发；v32 不参与次级触发召回，更接近经典版本。切换引擎不会删除已有记忆。

监控页显示最近一次真实召回：使用的上下文、命中的记忆、分数与命中原因、常驻/最近楼层/普通结果、Sticky 状态以及去重状态。监控只记录结果，不会改变召回排序。

默认情况下，MemoryPilot 的召回完全基于关键词与文本匹配（主关键词硬命中 / 中文 n-gram 弱匹配 + 辅助关键词 + 楼层距离 + 新鲜度 + 召回类型），不调用任何 AI 接口。开启下面的向量召回后，每个评估轮会额外调用一次 Embedding 接口。

### 向量召回（Embedding）

在「API 配置」页下方的 **向量召回（Embedding）** 区域可以接入任何 OpenAI 兼容的 `/v1/embeddings` 接口（例如 Qwen3-Embedding-8B、text-embedding-3、SiliconFlow 等），填写 URL、Key、模型名，可选 `dimensions`。该配置与主 API 相互独立，默认关闭。

三种召回模式：

| 模式 | 召回条件 | 排序分数 |
| --- | --- | --- |
| 关键词 | 主关键词命中（旧版行为） | 关键词匹配度×0.65 + 召回类型×0.10 + 新鲜度×0.15 |
| 混合（默认） | 主关键词命中 **或** 余弦相似度 ≥ 阈值 | 关键词分×(1−w) + 相似度×w，`w` 为「向量权重」 |
| 纯向量 | 余弦相似度 ≥ 阈值 | 相似度×0.75 + 召回类型×0.10 + 新鲜度×0.15 |

混合 / 纯向量模式下，没有主关键词的记忆也可以被向量召回；辅助关键词只在关键词命中时作为软惩罚参与。相似度阈值一般取 0.45~0.65，越高越严格。

实现细节：

- 记忆向量（事件名 + 摘要 + 关键词）按「模型 | 维度 | 文本哈希」缓存在浏览器 IndexedDB，文本不变不重算；编辑记忆、更换模型或维度会自动重新计算。可以用「为当前聊天记忆建立向量」一次性预热，用「清空向量缓存」强制重算。
- 每个评估轮只把最近上下文（默认最近 1500 字符）送去 embedding 一次，非评估轮沿用 Sticky，不调用接口。
- 接口失败、超时或配置不完整时，本轮自动回退关键词召回，不会出现“召不回任何记忆”的情况；召回监控会显示回退原因、每条记忆的相似度以及是否由向量召回。
- 常驻记忆与最近楼层记忆不参与向量计算；面板中的「即时模拟」只按关键词计算，含向量的真实结果请看召回监控。
- Embedding 配置随「设置 → 导出 / 导入」一并备份；向量缓存属于浏览器本地数据，不随导出文件迁移。

## 自动楼层总结

在“楼层总结”设置中可以开启自动总结。

默认设置为：关闭、每 20 楼总结一次、从第 1 楼开始、成功后保留最后 6 楼不隐藏、按 AI 建议导入。

自动总结在用户发送消息后、下一次 AI 回复生成前开始。它会把待处理楼层交给总结 API，并将结果整理为记忆。按 AI 建议导入时，AI 会分别判断常驻、主要触发和次级触发；常驻会受到数量限制，普通事件会更多进入主要触发或次级触发。

可选功能：

- 按指定类型统一导入；
- 编辑、保存或恢复默认的自动总结 Prompt；
- 总结成功后隐藏旧楼层；
- 设置始终保留的最后若干楼层；
- 手动重试失败区间。

“隐藏”只会让 MemoryPilot 在后续 AI 上下文中排除已成功总结的旧楼层，不会删除聊天原文，关闭后可以恢复显示。

如果一次总结失败，原区间会保留；下一周期会把新楼层与失败区间叠加后再次总结。删除聊天楼层后，自动总结进度会按受影响范围回退，后续楼层重新累计。运行时会显示“正在总结、成功、失败或聊天切换未写入”等状态。

## Prompt 编辑

以下 Prompt 都可以在面板中编辑、保存和恢复默认：

| Prompt | 用途 | 可用变量 |
| --- | --- | --- |
| 手动楼层总结 | 将选定楼层整理为候选记忆 | `{{content}}` |
| 自动楼层总结 | 按间隔总结聊天楼层 | `{{content}}` |
| 关键词重构 | 为外部总结或已有记忆生成关键词 | `{{event}}`、`{{summary}}`、`{{entities}}`、`{{timeLabel}}`、`{{floorRange}}` |
| 合并记忆 | 将多条记忆整理成一条 | `{{memories}}`、`{{context}}` |

自定义 Prompt 是全局设置，会在不同聊天之间共用。不要删除正在使用的变量，否则对应内容无法替换。

## 存储、备份与删除回退

记忆主体、聊天配置、Sticky 状态和备份快照保存在 SillyTavern 的扩展设置中；浏览器本地缓存只用于加速读取和保存运行日志。聊天元数据只保留轻量恢复指针，Prompt 注入变量只放在：

- `mp_recall_pin`：常驻记忆
- `mp_recall_ctx`：主要/次级触发记忆

MemoryPilot 会优先读取本地缓存，再读取扩展设置，并兼容旧版聊天元数据和旧版本地数据。变更检测会避免无变化的重复写入。

记忆按聊天隔离。单人聊天以「聊天 + 角色」为作用域；群聊以「聊天 + 群」为作用域，不受当前发言成员影响。4.0.1 之前的版本在群聊中会按发言成员拆分存储，升级后首次打开群聊会自动把这些记忆合并回来，并提示找回条数。

从 SillyTavern 1.16 的聊天备份导入并作为新聊天打开时，MemoryPilot 可以根据恢复索引复制原聊天的记忆和配置。清理旧版 metadata 后，恢复索引仍会保留，不会破坏备份恢复。

删除聊天楼层时，受楼层范围影响的记忆和自动总结进度会回退。手动删除的记忆不会因为普通存储恢复自动回来；只有主动恢复快照或备份才会恢复。

## API 配置

API 配置独立于 SillyTavern 的主 API，支持：

- OpenAI 兼容接口
- Claude
- Gemini

这些接口用于手动总结、自动总结、关键词重构和合并记忆。面板包含超时与重试处理；API 配置由 MemoryPilot 独立保存，不会替换 SillyTavern 的主 API 配置。

同一页下方还有独立的 Embedding 接口配置（OpenAI 兼容 `/v1/embeddings`），仅用于向量召回，详见「召回 → 向量召回（Embedding）」。

## 导入、导出与更新

“设置”中可以导出记忆、召回设置、API 配置、自动总结设置和 Prompt。导入时可以选择合并现有内容或覆盖现有记忆。

“更新到最新版”会调用 SillyTavern 的扩展更新功能，自动识别安装位置、拉取仓库最新版本，并在成功后刷新页面。通常不需要手动修改版本号；如果更新后界面没有变化，可使用“重载应用更新”。

## 安装

### SillyTavern 扩展安装

在扩展管理器中安装本仓库：

```text
https://github.com/Killuaisaack/MemoryPilot
```

### 手动安装

将项目目录放入：

```text
public/scripts/extensions/third-party/MemoryPilot/
```

安装或升级后刷新 SillyTavern。若之前使用过旧版 task 或旧版 MP，建议先确认旧任务已停用，避免同一轮重复处理。

## 常见问题

### 为什么看不到输入区快捷按钮？

快捷按钮默认关闭。打开 MemoryPilot → 设置 → 显示输入区快捷按钮即可；魔法棒菜单中的 MemoryPilot 入口始终可用。


### 自动总结没有立即出现？

自动总结按楼层间隔触发，并在用户发送消息后、下一次 AI 回复前运行。失败时会保留待处理区间，在下一周期叠加后重试。

### 删除楼层后记忆为什么还在？

只有楼层范围受影响的自动总结进度和相关记忆会回退；不属于该范围的手动记忆不会自动删除。可以在记忆列表中手动删除，或恢复到合适的备份快照。
